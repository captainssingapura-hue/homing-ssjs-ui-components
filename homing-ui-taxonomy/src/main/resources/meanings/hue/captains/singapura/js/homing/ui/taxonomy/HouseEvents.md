# The house's tree of events

## Pointing

What the user's pointer does to the component.

## Dragging

What happens as the user takes hold of the component and moves it.

## Editing

What happens to the component's value as the user gives it.

## Asking

What the user asks of the component beyond its value: to send, to go away, to have the thing itself.

## Loading

What happens as what the component shows arrives, or fails to.

## Timing

What happens to the component as time passes, with nobody touching it.

## Scrolling

What happens as what the component holds is scrolled through.

## Click

The user pressed the component and let go on it: the act a button, a link or a crumb is for.

## Press

The user's hand came down on the component, before it is let go: for what must answer at once, such
as a veil that closes what it stands behind.

## Grab

The user took hold of the component to move it: a chip, a knob, a divider, a drawer's handle.

## Drag

The user moved the component while holding it.

## Drop

The user let the component go where it now is, after moving it.

## Input

The component's value changed while the user is still giving it: a letter typed, a knob moved along.

## Commit

The user is done with the component's value: Enter pressed, the field left, the knob let go.

## Submit

The user asks for what was filled in to be sent: a form, a search, a message.

## Dismiss

The user asks for the component to go away without anything being chosen: Escape, a press outside
it, a swipe.

## Activate

The user asks for the thing the component stands for: Enter on a row, a double click on an item.

## Load

What the component shows has arrived: a picture, a page of rows.

## Fail

What the component shows could not arrive: a picture that will not load, an upload that broke.

## Expire

The component's time ran out, and it goes or changes by itself: a notice that leaves when it has
been read.

## ReachEnd

What the component holds has been scrolled to one of its ends, where more could be brought in.
